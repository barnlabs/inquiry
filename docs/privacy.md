# Privacy

Inquiry is local-first. The CLI does not create an account, send analytics, or upload reports to BarnLabs. Before live research, `inquiry plan` creates a deterministic execution plan listing each service, destination, outbound field, purpose, and risk. A networked run requires the exact plan fingerprint or the separately enabled automatic-public-web mode. Their privacy policies and logs apply.

Current live destinations can include World Bank, Wikipedia/Wikimedia, Wikidata, MedlinePlus, OpenAlex, Open Library, NASA Science, GDELT, Wikimedia Commons, USAGov and the White House for a U.S. current-president query, UK Parliament and The Royal Family for an exact current-UK-monarch query, and an explicitly configured SearXNG endpoint. GDELT results are discovery leads only; social-image URLs are never treated as verified or rights-cleared media. An approved research query is sent only to the connectors listed in that exact plan. SearXNG must use HTTPS, with HTTP allowed only on loopback for local development. The endpoint is trusted user configuration; URL checks reject common unsafe literal and reserved-name cases but do not provide rebinding-proof DNS pinning. Exact-place resolution sends the location phrase to the configured Nominatim service. `medication-evidence` sends one or two supplied medication names to openFDA. `airport-status` sends one three-letter airport identifier to the FAA NAS status endpoint. `live-events` sends only fixed `status=open&limit=50` parameters to the exact NASA EONET endpoint after an exact plan approval or eligible automatic-public-web approval; it never sends the planning text or an identifier. Do not place patient details, private-person targeting, credentials, confidential investigations, classified material, or unpublished research in a live request.

Calculation, conversion, formula, local reference tables, graph, report rendering, timeline rendering, Word-compatible RTF and Excel-compatible CSV export, public-report study-pack generation, capability inspection, airline/package handoff creation, local FAA archive lookup, and InquiryStudy indexing/search/export are local. The macOS app defaults to **Ask every time**: it runs a local privacy check and local execution plan, then shows the exact destinations and outbound data before the first request. **YOLO mode** in Settings automatically approves only engine-marked public-query plans; sensitive context, scoped identifiers, ambiguity, and unsupported intent still fail closed. **Always offline** suppresses connector requests. The EONET command follows the same rule: `--offline` wins over either approval mode and fails before an HTTP client is built. In the native Live workspace, the same approval review separately discloses that constructing the in-app MapKit view can send its world viewport, IP address, request timing, and device/network metadata to system-managed Apple Maps services; the map is not constructed before that approval. YOLO mode's confirmation names this extra native display behavior. These modes do not grant account access, background polling, or future authority beyond their stated scope. Detection is not perfect, so users must still review every live query.

Package, flight, live-aircraft, and aircraft-registration identifiers are detected before general research connectors are selected. A guarded query produces a local abstention report with no connector attempt and directs the user to an explicit scoped tool. Package handoffs mask the identifier in output and omit it from the URL by default. `--deep-link` or `include_identifier_in_url: true` is an explicit disclosure to the selected official carrier and can also retain the identifier in browser history. Airline handoffs make no request. Local FAA archive lookup accepts one N-number and omits owner names, addresses, serial numbers, Mode S codes, coordinates, movement history, bulk enumeration, and reverse-owner lookup.

InquiryStudy reads only a user-selected course folder. It does not scan the home directory, recent files, browser data, mail, or cloud drives automatically. The Rust indexer initiates no network request, but macOS or an iCloud, OneDrive, Google Drive, or other File Provider may hydrate a cloud-only file during the read. Export locations may also sync independently. The native app stores indexes under the user's Application Support directory with owner-only permissions, exposes the location, and provides confirmed deletion. Index JSON contains source excerpts and must be protected like the original notes.

The MCP server's local-study tools are disabled by default. When an operator explicitly sets `INQUIRY_ENABLE_LOCAL_STUDY_MCP=1`, the server can search only a named `*-study-index.json` file under a confined, non-symlink `reports/` directory; it still cannot choose or index an arbitrary path. The MCP host and any model provider it uses may receive every query, filename, locator, normalized excerpt, risk label, and checksum returned by these tools. That disclosure is separate from Inquiry's own connector networking. Use the CLI or macOS app instead when material must remain device-local.

Flagged assessments, credentials, private or clinical records, restricted material, and embedded instruction-like excerpts are blocked from local recall export by default. Classification is heuristic and must not be treated as a FERPA, HIPAA, academic-integrity, or secret-scanning guarantee.

Generated HTML dossiers never fetch remote images or data; their media previews remain explicit external links. The macOS app opens these dossiers in a nonpersistent in-app viewer that blocks automatic remote navigation. Private owner-only temporary files are removed when the dossier closes, a new inquiry begins, and during bounded launch cleanup. Source links require an explicit click and may open outside Inquiry.

The macOS app has a separate **Settings → Privacy → Load cited portrait previews automatically** preference, enabled by default for an already approved live run and disabled in offline reports. It is not promoted as a switch in the main research header. The execution plan discloses the Wikimedia preview destination before the research run is approved. Each eligible result still shows loading, failure/retry, offline, or preference-off state. When enabled, it fetches only an identity-bound portrait preview whose exact Wikimedia Commons record passed Inquiry's URL, type, byte-size, pixel, creator, description, and explicit reuse-basis checks. Recent-event media is never automatic: after a public event title is resolved, Inquiry may perform one disclosed bounded Commons refinement, retains only a query-relevant file with accepted machine-readable reuse terms, and still requires the user to choose **Load in Inquiry** on that result before the preview request. The event identity, recency, and depicted subject remain discovery claims unless separately verified. The native loader uses an ephemeral session with no cookie or credential store, rechecks redirects against `upload.wikimedia.org`, enforces a 5 MB transfer limit, uses ImageIO to reject multiple frames and oversized dimensions before decoding a bounded thumbnail, and checks the cited aspect ratio when dimensions were supplied. Cancellation uses a synchronized single-completion state machine and stale-load generation guard. This preview request still reveals the viewer's network address, request timing, and image URL to Wikimedia. Turn the portrait preference off to stop automatic portraits; event media remains per-result opt-in regardless.

Avoid entering private personal data, PHI, credentials, sealed records, confidential investigations, or information you are not authorized to share with those services. Use `--offline` for sensitive planning and delete generated reports when retention is no longer justified.

Inquiry does not attempt to reverse location anonymization, infer protected traits, assemble individual risk scores, or access authenticated sources. Project logs and bug reports must redact queries and report contents unless the reporter deliberately supplies synthetic or public test data.
